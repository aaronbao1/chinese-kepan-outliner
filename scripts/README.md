# scripts/

The quickstart, the fetch scripts, the outline validator and the eval-set registry tool. Each script states its inputs and outputs in its header. Fetched data goes under `data/raw/`, which is gitignored: nothing third-party is redistributed, and every fetched file is pinned by sha256 in [`CHECKSUMS`](CHECKSUMS), or by commit for the whole-corpus clones. Every fetch script is idempotent and offers `--check`, which re-verifies what is on disk; the ones that call a web API pace their requests. Commands below are written from the repository root; each script finds the root itself.

From a fresh clone, `bash scripts/quickstart.sh` is the shortest path to a run.

## Running the pipeline

| Script | What it does |
|---|---|
| `quickstart.sh` | Fresh clone → outliner run, offline, with no model and no API key. (1) Makes `pipeline/.venv` with the first Python ≥ 3.11 on the PATH (`QUICKSTART_PYTHON` overrides it) and installs the package editable with its dev extra. An interpreter whose `pyexpat` cannot load (seen with Homebrew Python 3.11 and 3.12 on recent macOS) is passed over, because `-m venv` fails in `ensurepip`; if no interpreter works and `uv` is installed, it uses `uv venv --managed-python --python 3.12` and `uv pip`. An existing venv is reused. (2) Fetches the root and commentary files the project names that are not on disk, with `fetch_cbeta.sh <ids>`. (3) Runs `python -m chinese_workflow.runner run ../projects/<id>/project.toml` from `pipeline/`; outputs go to `data/processed/<id>/`. Arguments: project ids (default `lotus-kuiji-dharani-comm`) or `--all`. It runs no tests; it prints the test command. |

## Fetching data

| Script | What it fetches, and where | What needs it |
|---|---|---|
| `fetch_cbeta.sh` | The 19 CBETA XML-P5 works it pins (`--list` prints them; about 35 MB), from `cbeta-org/xml-p5` at tag `2026R2`, into `data/raw/cbeta/`, bytes verbatim and size-checked against the tag's git tree, plus a snapshot of `https://cbeta.org/copyright` as `LICENCE-NOTICE.{html,txt}`. CBETA file ids as arguments fetch only those works (`bash scripts/fetch_cbeta.sh T09n0262 T34n1723`). A recorded `CHECKSUMS` line whose file has the same bytes is kept in place, so a fetch in a fresh clone leaves the working tree unchanged. `--check` exits 0 when every XML file matches; the licence page differs on every download (per-request e-mail obfuscation), so `--check` reports it as `CHANGED` without failing, and `--force` re-records it. | Every project under `projects/`; the Kuiji gold's builder; most tests that read CBETA text. |
| `fetch_cbeta_xml_p5.sh` | Shallow clones of the whole CBETA corpus: `cbeta-org/xml-p5` at tag `2026R2` (commit `dbdea410`, 5,017 files) into `data/raw/cbeta/xml-p5/`, and the frozen `cbeta-org/xml-p5-2018` archive (commit `1a9010b2`, 4,717 files) into `data/raw/cbeta/xml-p5-2018/`. About 5 GB together. Pinned by commit, not per file; `--check` verifies that both clones sit at the pinned commits and are clean. | The three CBETA 科判 golds (X0268, P1573, D8842) and their tests; tests and experiment rows that read CBETA files outside `fetch_cbeta.sh`'s list (the out-of-domain rows of E06 and E07); the survey below. No project needs it. The pipeline reads a CBETA file from `data/raw/cbeta/` first and falls back to the 2026R2 clone (`common/paths.py`, `cbeta_xml_path`). |
| `survey_cbeta_xml_p5.py` | A corpus-wide census of CBETA's `cb:mulu` markup over the 2026R2 clone (type × level counts, and every node typed `科判` with its text and line) into `data/raw/cbeta/survey/`; `--diff` adds a Taishō `lb`/`pb` comparison against the 2018 archive and `--census` a count of Taishō notes against the apparatus. Stdlib plus lxml; deterministic. | `tests/unit/test_gold_cbeta_mulu.py` checks the three CBETA 科判 golds' node counts against `mulu-nodes-kepan.tsv`. |
| `fetch_cbeta_metadata.sh` | DILA's per-work metadata tables (`T.json`, `X.json`: Taishō or Xuzangjing division, CBETA 部類, byline, dynasty), with that repository's README and MIT licence, from `DILA-edu/cbeta-metadata` at commit `af914b8d`, into `data/raw/cbeta-metadata/`. | Optional input of the survey, which uses it to label each file's division. |
| `fetch_cbeta_api.sh` | Responses of the CBETA API (`https://cbdata.dila.edu.tw/stable/`: `works/toc`, `toc`, `juans`, `search`, `search/kwic`) into `data/raw/cbeta-api/`. The server is unversioned, so a `--check` mismatch after a fresh fetch means the served text changed. | `tests/unit/test_ingest_lines.py` uses the `works/toc` trees as the oracle for the ingested `cb:mulu` tree; the T0262, T1718 and T1723 trees are also committed under `tests/fixtures/cbeta-api/`, and the others (T1602, T1605, X0268) come from here. |
| `fetch_dila_sdp.sh` | The CHIBS 法華經數位資料庫 (sdp.chibs.edu.tw) reader files: the seven 卷 of T0262 with its 2,017-node 科判 and Taishō line anchors, the full `getTreeNode` trees of T0262 and T1718 (through `sdp_tree.py`), and the 9 of T1718's 20 卷-halves that the server serves (the other 11 fail server-side), into `data/raw/dila-sdp/`. sdp publishes no licence, so this data is used for evaluation only and never committed. | The Zhiyi golds: `cd pipeline && .venv/bin/python -m chinese_workflow.eval.gold.sdp` builds them into `data/raw/dila-sdp/gold/` (`data/EVAL-SETS.md`, "Rebuilding and checking"). The sdp tests and every Zhiyi row of E01, E06 and E07 need them. |
| `sdp_tree.py` | Helper of `fetch_dila_sdp.sh`: a depth-first walk of sdp's `getTreeNode` API into `data/raw/dila-sdp/tree-<doc>-full.json`, one request at a time, with checkpoint and resume. A node the server keeps failing on is recorded with `fetch_error`, never dropped. `--stats` recounts a written tree offline. Stdlib only. | `fetch_dila_sdp.sh`. |
| `fetch_dila_ybh.sh` | DILA's 瑜伽師地論資料庫 (ybh.dila.edu.tw) standalone 科判 files and text+科判 archives for T1579, T1602 and T1605, plus the download page that carries the "© CC BY-SA 4.0" footer, into `data/raw/dila-ybh/`. | The builder of the two YBh golds (`eval/gold/ybh.py`) and `tests/unit/test_gold_ybh.py`. |
| `fetch_bdrc.sh` | The BDRC ontology `core/bdo.ttl` from `buda-base/owl-schema` at commit `4f3bf4a1`, into `data/raw/bdrc/`. | `tests/unit/test_export.py` checks that every BDRC term the knowledge-graph export writes exists in the ontology. |

The scripts that fetch the data the projects, tests and results use are `fetch_cbeta.sh`, `fetch_cbeta_xml_p5.sh` (then `survey_cbeta_xml_p5.py`), `fetch_cbeta_api.sh`, `fetch_dila_sdp.sh` (then the sdp gold build), `fetch_dila_ybh.sh` and `fetch_bdrc.sh`. Licences and source details are in [`../data/README.md`](../data/README.md).

## Checking outlines and the registry

| Script | What it does |
|---|---|
| `validate_outline.py` | Validates outline JSON against `context/baseline/outline-schema.json`, or `outline-schema-zh.json` when `metadata.outline_profile` is `zh-kepan`, plus the structural rules a JSON Schema cannot express: ids, pre-order, parent, level and path, sibling order, span order, parent/child containment, text-id prefixes, and the sūtra-mode rules (D15 in [`../docs/chinese-workflow-mapping.md`](../docs/chinese-workflow-mapping.md)). Prints PASS or FAIL per file and writes nothing; exit 0 when all pass, and `--strict` counts warnings. Importable: the gold builders, the pipeline and the tests call `validate_document` / `validate_file` in-process. |
| `eval_sets.py` | Recomputes the computed parts of the eval-set registry `data/eval-sets.json` (each dataset's `file_metadata` and `counts`, from the files) and the generated tables of its guide `data/EVAL-SETS.md`. `--write` rewrites both; `--check` (the default) compares and exits 1 on a difference. Eval-only files absent from `data/raw/` keep their recorded numbers. Stdlib only. A thin wrapper: the logic, and the read access the scorer uses (`split_of`, `dataset`, `served_juan_halves`, `in_scoring_scope`), are in `chinese_workflow.eval.registry`. |

## `CHECKSUMS`

Not a script: one line `sha256  path  # provenance` (tag or commit, fetch date) per fetched raw file. Each `fetch_*.sh` script owns the lines under its own `data/raw/<source>/` prefix; `fetch_cbeta.sh` owns only the files directly in `data/raw/cbeta/`, and the `survey/` and `xml-p5-2018/` lines belong to `fetch_cbeta_xml_p5.sh`, which appends them by hand. Verify with `bash scripts/fetch_<source>.sh --check`. Files read out of the pinned `xml-p5` clone (X11n0268, P167n1573 and D14n8842, for the `cbeta-mulu-kepan` golds) get no lines of their own: `fetch_cbeta_xml_p5.sh --check` checks the clone by commit, and each gold's `PROVENANCE.md` states the sha256 of the file it was built from.

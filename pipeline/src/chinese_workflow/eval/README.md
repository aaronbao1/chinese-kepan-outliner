# eval — independent outline vs gold kēpàn; chunk invariants; translation sample

What is scored is the *independent outline* (`outline.json`, profile `zh-kepan` of `context/baseline/outline-schema-zh.json`, D15, which extends `context/baseline/outline-schema.json`), not the outlined-text: gold outlines are independent outlines in the same schema, so the comparison is tree-to-tree. The outlined-text is the same nodes anchored to spans and is what the chunker consumes; its coverage % and fallback rate are reported here too.

**Metric decision (R06, 2026-09-17; HYPOTHESIS until the E02/E03 pilots).** Primary: hierarchical node F1 over (explained locator, depth, parent path), reported twice — **S-F1** (structure only) and **F-F1** (structure + `origin` label) — with a stated convention (all non-root nodes; micro over nodes, macro over texts) and a locator tolerance `t` printed with every score (default `t = 0` until the E02 pilot picks a value). Matching is on the *explained* locator; the enumeration (first-appears) locator is optional in the key (E02 tests with/without). Secondary diagnostics, never fused into one number: per-depth-band F1; tree-edit-distance similarity with a locator/depth-aware custom cost (APTED, PubTabNet `metric.py` pattern; licences per R06 F20: apted MIT, PubTabNet `metric.py` Apache-2.0, HRDoc unlicensed, so copy nothing from it); per-level Pk/WindowDiff as boundary-only diagnostics (vendor the formulas; `segeval` is unmaintained since 2017); origin per-category F1 and kappa. Gold nodes therefore need `explained_locator`, `depth`, parent path/id, `origin`, heading text (`enumeration_locator` optional); reserve 2–3 texts for double annotation to compute a per-depth human ceiling with the same scorer. A gold-format adapter must also read DILA YBh TEI (`div level=n`/`head`/`p`, anchored to Taishō page/column/line) so those texts can serve as a second gold (R04). (2026-10-04: the TEI masters are unpublished, so the YBh golds were built from DILA's `-kp.txt` files instead, structure only, by `gold/ybh.py`; R08 F19 shows YBh's online reader can anchor them.) Also reported: text coverage % and `unoutlined` fallback rate (from the anchor step); agreement with a Tibetan-side outline (R03/R07; only ch. 1–11 of T1723 have a Tibetan counterpart; not built). Chunk invariants: size bound, leaf-bounded, contiguous, full coverage. Translation sample quality for E05: method not yet designed. Gold outlines live in `data/reference-outlines/`, keyed by (text, commentary) pair. The Tibetan workflow defines no evaluation of outlines, so this procedure is our own (R06 H6).

## `gold/` — gold-outline builders (subpackage, 2026-09-22)

**Input:** an external or hand-written outline source plus the CBETA XML it anchors to. The sources are sdp's 科判 pages and trees, a hand-authored `outline.txt`, CBETA's `cb:mulu type="科判"` markup and DILA YBh `-kp.txt` files. **Output:** *gold outlines*, i.e. independent outlines under profile `zh-kepan` that pass `scripts/validate_outline.py`: committed golds under `data/reference-outlines/<text-id>/<scheme_id>/`, and the eval-only sdp golds under `data/raw/dila-sdp/gold/` (gitignored). Modules:
- `common.py`, shared helpers;
- `sdp.py`, the two sdp golds;
- `sdp_check.py`, the heading check of the T1718 sdp gold;
- `authored.py`, the hand-authored golds (Kuiji);
- `cbeta_mulu.py`, X0268 / P1573 / D8842;
- `ybh.py`, T1605 / T1602.

Their inputs, outputs and rules are in `gold/README.md`. The package may import `chinese_workflow.ingest`, never `outline`, `chunk` or `translate`.

**The registry.** `data/eval-sets.json` lists every gold with its path and split scope. It also holds the dev / validation / test / reserve split spans and is the single source of truth for them: `gold/sdp_check.py` keeps a copy of the T1718 spans, which `tests/unit/test_gold_registry.py` checks against the registry. The scorer should read paths and spans from there, not hard-code them, through `registry.py` in this package (`load_registry`, `dataset`, `split_of`, `split_spans`, `served_juan_halves`, `in_scoring_scope`; standard library only). `scripts/eval_sets.py` is a thin CLI over it that recomputes the registry's computed blocks and the guide's tables. Its guide `data/EVAL-SETS.md` ends with "Using these sets", the rules the scorer has to implement:
- which nodes are scorable (E01: `commentary.explained` not null, not the `unmapped` flag);
- the E01 match-key issue (sdp anchors the node's text start, Zhiyi's formula comes later);
- scope from `metadata.coverage_spans` and the meaning of `truncated`;
- inclusive gold ends vs end-exclusive split spans;
- `count_mismatch` and `anchor_inherited`;
- structure-only scoring for the YBh golds;
- no headline score on the draft Kuiji gold before review.

## Scorer (`score.py`, 2026-09-27)

**Input:** a predicted `outline.json` (zh-kepan, `gold_status: prediction`) and a gold named by its registry dataset id; the key file's CBETA XML (`data/raw/cbeta/`) for line order. **Output:** `metrics.json` (schema `outline-metrics/1`): `settings`, `disclosures`, `counts`, `rows`, `child_count`, `guard` and, on the dev split only, `diagnostics` (node ids). Aggregate numbers only: no gold heading or note is written or printed.

```
cd pipeline
.venv/bin/python -m chinese_workflow.eval.score --pred outline.json --gold kuiji-xuanzan \
    [--key commentary.explained|root_text.start|commentary.span_start|structure] [--t 0] \
    [--split dev|validation|test|reserve|all] [--frozen TAG] [--out metrics.json]
```

API: `score(pred, gold_id, *, key=None, t=0, split=None, frozen=None, registry=None, gold=None, line_orders=None) -> dict`. `gold` passes a gold dict (tests; `gold_id` is then a label, and the registry entry of that id still applies when there is one); `line_orders` (`{file id: [lineheads]}`) replaces the XML as the source of line order.

What it implements (the module docstring cites the EVAL-SETS item of each rule):
- **Key** from the dataset: `commentary.explained` for E01 golds (`split_scope.by`), `root_text.start` for the root-anchored sdp T0262 gold, `structure` (heading + depth + parent path) for the YBh golds. Lines are compared without `:n`. `commentary.span_start` (never a default; E06 review, 2026-10-02) reads a prediction at `locations.commentary.span_start`, the text-span start the outliner writes beside `explained` (a first child inherits its parent's start, `span_start_inherited`, unless the parent is editorial or its start lies before the build's first line `metadata.span.first`, in which case the build's first child is only the first child the build has and keeps its own `explained` line), and a gold node at its own `span_start` where it has one, else at its `explained` line (the golds' text-span start; no gold is chained). A prediction without the field has no key: add it with `python -m chinese_workflow.outline span-start outline.json --out …`.
- **Matching** top-down, one-to-one: siblings are aligned in line order within t lines (a DP: most pairs, then least total line distance, then least total sibling-index difference); structure mode, which has no line order, pairs siblings greedily by equal heading. A child matches only under a matched parent. Nodes with a null key are not scored on either side; their scorable descendants attach to the nearest scorable ancestor. **S-F1** counts matched pairs; **F-F1** also needs equal `origin` after an explicit mapping (`imported` counts as `explicit`).
- **Rows** at the requested t and always at t = 0 and t = 1; each with P/R/F/TP/FP/FN, the same without `anchor_inherited` gold nodes, per depth, and a **locator-only** F1 (key lines as a multiset, matched within t) that separates detection from attachment. Without the XML, t = 0 falls back to string equality and t > 0 is reported unavailable. Under `commentary.span_start` each row also carries `without_span_start_inherited` (S-F1, F-F1 and locator-only without the predictions whose `span_start` is inherited; `predictions_dropped` counts them), the mirror of the `anchor_inherited` block.
- **Scope:** `coverage_spans` (Kuiji: an unmatched in-scope prediction is FP even under `truncated`; out of scope, neither); without them, an unmatched prediction whose nearest matched ancestor is a `truncated` gold node is neither; served 卷-halves of the sdp T1718 gold via `registry.in_scoring_scope`; `merged_range` absorbs split siblings into one match: within t lines of it in locator mode; in structure mode the unmatched siblings beside its pair with no unmatched gold sibling between, capped by a range label such as `K5-9`.
- **Child counts** against `child_count_announced`; a disagreement at a `count_mismatch` node is counted as the source's.
- **Splits:** default dev (disclosed); `test`, `reserve` and `all` need `--frozen`; OOD golds need `--frozen` (`SplitGuard.check_gold`); the counted key lines pass `SplitGuard.check_lines`. In root-text scoring a predicted node on a known gold node's root line takes that node's split; any other predicted node, and a gold node without its own split locator, takes the most protected split of the commentary between its nearest known gold neighbours (EVAL-SETS, "Root-text experiments and the splits"). Under `commentary.span_start` a gold node keeps the split of its `explained` line and a prediction takes that of its `span_start` line.
- **Disclosures:** `gold_status`, `seeded_by`, `eval_only`, split (and whether defaulted), t, key, nodes out of scope, pairing warnings (item 12). `headline: false` for a draft-unreviewed, imported-unchecked, synthetic or prediction gold and for any dev or validation score.
- **Diagnostic fields (review of E06, 2026-10-02, A1; never headline values):** every row also carries `fn_split` — a FN is a *frontier* miss when its scoring-tree parent is matched or the root, else *cascaded*; a frontier miss is `frontier_line_detected` when a free (unpaired, unabsorbed) predicted node lies within t of its key line, i.e. the line was found and the node attached or levelled wrongly — `fp_by_kind` (`listed_only`: `announced == explained` with a `:offset`, the anchor's rule for a node the commentary lists but never takes up; `commentary_internal`: `node_class`; `taken_up`: the rest), `key_lines` (counted nodes and distinct key lines per side; `recall_cap_one_node_per_line` = distinct / counted gold, 5/12 on the T1718 dev row where sdp keys a parent and its first child on one line), and the root-text TP rule side by side: `tp_rule: gold_counted` is the headline (a matched pair is TP when the gold node is counted, FP runs over counted predictions, so a prediction can be uncounted while its gold twin is not — model-only-T0262-xu-root's dev t = 1 S-F1 0.625 rests on three such pairs), `s_f1_both_counted` requires both sides counted (0.308 there), with `tp_uncounted_pred` and the check `tp_le_counted_pred`. Which rule becomes the headline is not decided (review Q4). The dev-only `diagnostics` block adds the ids behind these: `tp_pairs` (`[pred id, gold id]`), `tp_uncounted_pred_ids`, `fn_frontier_gold_ids`, `fn_frontier_line_detected_gold_ids`, `fn_cascaded_gold_ids`, `fp_pred_ids_by_kind`. Still ids and counts only: no gold heading or note is written.
- **Attachment-tolerant triple (review of E06, 2026-10-02, A2; diagnostic rows, never the headline):** every available row also carries `ancestor_consistent` (P/R/F/TP/FP/FN of the *ordered ancestor-consistent* mapping with the most both-counted pairs (then the most pairs) over the row's counted nodes and their scorable ancestors — a pair needs key lines within t, ancestors map to ancestors, sibling order is kept: an ordered tree-edit mapping with unit insert/delete and no relabel, computed by a memoised forest recurrence; counted first, so in the line-order keys `s_f1_both_counted`'s TP never exceeds it (in structure mode the top-down match is greedy and can exceed the ordered mapping); `mapped_pairs` is that mapping's size, uncounted ancestors included), `reanchor` (the row's top-down pairs extended by letting each unmatched counted gold node take a free predicted node within t and aligning its subtree below; `anchors` = how many such re-anchors) and `depth_offset_hist` (`hist` of level(pred) − level(gold) over line-matched pairs, `mode`, `share_at_mode`, `share_within_1_of_mode`). TP is both-counted (as `s_f1_both_counted`); a prediction exempt under `truncated` is neither TP nor FP. **Read the three together, never AC-F1 alone:** a flat prediction maps every gold leaf and reaches AC-F1 0.68 on the Kuiji 陀羅尼品 dev subtree, but with 41 anchors and offsets spread over −6…−1, whereas one mis-attached subtree reads as a high AC-F1 with 1 anchor and that subtree's offset as the mode (gold against itself: 1.000, 0 anchors, every offset 0). On the E06 dev cells: tier2-T1718-dev AC-F1 0.195 with 4 anchors at t = 0 (attachment explains at most 4 of 11 misses); tier2-T0262-xu-root 0.842 with 1 anchor at t = 1 (one top-level slip); model-only-T0262-dharani-root 0.658 / 0.842 at t = 0 / 1, depth-offset mode −1 at both t (15 of 25 and 17 of 33 pairs; the rest mostly −2: the model's tree sits one or two levels shallow). Rows whose two forests exceed `AC_MAX_FOREST_NODES` (600 nodes; X0268, the YBh golds) report the triple as `available: false` with the size; so does a row whose recurrence overflows the interpreter's recursion limit (a forest of about 500 nodes or more on Python 3.11), with the limit; `settings.diagnostic_forest_cap` records the cap. `merged_range` is not modelled by the mapping (S-F1 aligns an absorbed sibling's children under the merged gold node; see the `score.py` docstring), which no row reaches today: every gold that carries it is above the cap. `summary()` does not print it.

Not implemented here: a tree-edit *distance* with locator/depth-aware costs (the ancestor-consistent mapping above is the unit-cost, no-relabel case; EVAL-SETS item 5's pruning is its forest restriction), Pk/WindowDiff, and `merged_range` splits in structure mode where no part carries the merged node's heading (they stay FP). A shifted prediction that also lacks a sibling can still mis-pair at t = 1 where a shifted node lands on the missing sibling's line. Tests: `tests/unit/test_eval_score.py`, on the synthetic gold and registry in `tests/fixtures/scorer/`, plus two gold-backed checks (the Kuiji dev subtree and the sdp T1718 dev nodes score 1.0).

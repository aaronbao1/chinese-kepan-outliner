# context — chunk → context bundle

**Status:** stub; the package holds only `__init__.py` (`pipeline/README.md`).

This stage gathers the context that helps translate a chunk. The outline node's topic-category (plus its location range) is the retrieval key. Project-level context (Project Instructions, glossary pointers) stays small and always loaded; this stage builds the per-chunk bundle (divergence D8 in `docs/chinese-workflow-mapping.md`).

Candidate context sources, with their status in research threads R03 and R05 (none is wired in yet):
- **Commentary passage** for the span — VERIFIED available: T1723 itself (its location is known from the outline in commentary-driven mode); second-order commentaries T1724, X0636–X0639 and 栖復's 要集 (Kanripo KR6d0030) as chunk-level context (R03).
- **Parallel canonical versions** — PARTIAL: (1) MITRA-parallel v2 bulk download (1,693,730 Skt–Chi / Chi–Tib records, CC BY-SA 4.0) into `data/raw/`; (2) DharmaNexus `POST https://dharmamitra.org/api-db/matches/` — pending terms (the DharmaNexus guide forbids populating third-party apps); (3) MITRA Search `POST /primary/` with `filter_source_language=zh`. DharmaNexus Chinese segment ids carry the Taishō page, column and line where the segment ends (`ZH_T09_0262_001:0001c14_0`; R05 F19, PARTIAL: 74 irregular T0262 ids, dropped verse pādas and 品-label leaks to handle). So a CBETA-line ↔ `segmentnr` table for T0262 can be derived offline from DharmaNexus's segment files and the CBETA XML; anything Dharmamitra-side that is driven from chunk ids needs that table first. (4) The CBETA API `search/similar` + `lines?linehead=` is the licence-clear, linehead-keyed Chinese–Chinese fallback (R05 F30, PARTIAL).
- **國譯一切經 rendering** — PARTIAL / BLOCKED: Dharmamitra has digitised "the majority of volumes", and its API returns a `kokuyaku_link` per Chinese segment (R05 F21, PARTIAL). Alignment granularity, volumes, rights and shareability are unknown (R05 H4).
- **Glossaries** — VERIFIED source: DILA glossaries API (`https://glossaries.dila.edu.tw/api/`, CC BY-NC-SA 4.0, includes Soothill–Hodous and Karashima). The Digital Dictionary of Buddhism has no automated-access tier (guest 20 lookups/day, quota explicitly anti-robot) — do not script against it (R05 H7). Era-specific term tables (Kumārajīva vs Xuanzang conventions) still HYPOTHESIS. The MITRA Translation Lexicon data (`dharmamitra/dharmamitra-lexicon`: zh-bo and sa-zh term pairs keyed by `segmentnr`; CC BY 4.0 by README statement only) is a second, machine-extracted source (R05 F27, PARTIAL).
- **Prior English translations** — the BDK Kubo–Yuyama PDF is all-rights-reserved: do not ingest (R03); others to be checked per licence.
- **Apparatus variants** for the span — from `ingest` (`apparatus.json`, R02 F5).
In the Tibetan workflow, past related translations and glossaries are supplied by hand.

**Output bundle:** `{chunk_id, outline_path, topic_category, chunk_type, entries: [{kind, text_id, loc, text, licence, how_found}], terms: [{surface, kind: transliteration | translation | native, glossary_hits}], entities: [...]}`. Retrieval is deterministic (loc range, 品 correspondence table, term lookup); a model-assisted step ranks and trims to a token budget and assigns `chunk_type` (Manual 2.2 §3b1 categories with Chinese variants: lemma, gloss, objection–answer, verse, dhāraṇī, narrative, list). Shape in `docs/architecture.md` §3.5.
